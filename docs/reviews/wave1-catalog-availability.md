## Yang sudah benar (diverifikasi sendiri)

- **Rumus uang D12 persis**: `unit = base + Σ delta`, `line = unit × qty`, `subtotal = Σ line`, `total = subtotal` (`catalog.service.ts:468-513`). Semua perhitungan `bigint`, keluaran string desimal, tidak ada `Number`/float. Overflow > 10^38-1 -> 400. Total 0 -> 400 (D12 butir 5).
- **Quote read-only**: probe saya menunjukkan `reserved_count` tetap 0 dan `version` slot tidak berubah setelah quote (sesuai D14 butir 7); test implementer juga mengasersikannya.
- **quoteHash kanonik**: deterministik, reorder baris = hash sama, beda kuantitas/opsi = hash beda (test lulus; `catalog.service.ts:533-543`).
- **Snapshot versi**: `menuVersion`, `groupVersion`, `optionVersion`, slot `version`, tenant/campus/timezone tersimpan di quote.
- **Otorisasi katalog**: semua mutasi memakai `requireTenant(..., 'tenant.menu.manage', client)` di dalam transaksi; staf pickup dengan grant palsu ditolak; setiap query menyertakan `tenant_id`; lintas tenant -> 404 (bukan 403) sehingga tidak membocorkan eksistensi; FK komposit menolak referensi lintas tenant (23503).
- **Audit katalog** (D14 butir 4): aksi `tenant.menu.item.price_changed`, `option.price_changed`, `item.sold_out/available/archived/restored`, `category|option_group|option.archived|restored`; `reason` wajib (dari DTO), actor dari sesi, ditulis dalam transaksi yang sama. Test `catalog.spec.ts` mengasersi urutan aksi+reason+actor secara persis.
- **Arsip**: tidak ada hard delete; `archived_at` dua arah (0007) dipenuhi termasuk pengosongan saat reaktivasi; item di kategori terarsip hilang dari discovery dan ditolak quote (D14 butir 2).
- **Discovery pembeli**: hanya `active`/`sold_out`, tanpa data staf/PII, escape metakarakter LIKE, cap 200 + `meta.truncated`, 404 untuk tenant archived/kampus nonaktif.
- **Konkurensi reserve (setelah fixture benar)**: probe saya dengan baris `orders` nyata — 12 reserve paralel pada kapasitas 5 = tepat 5 sukses, 7 gagal 409 "full", `reserved_count=5`, `version` tetap 1 (D3). Rekonsiliasi `reserved_count = COUNT(status IN ('reserved','consumed'))` bertahan setelah 2 release + replay (R1-18).
- **Release/consume/move (snapshot sekarang)**: `released_at`/`consumed_at`/`updated_at` di-set eksplisit, replay release/consume = `false` tanpa memulihkan kapasitas dua kali, consume tidak membebaskan kursi, move mengunci dua slot berurutan `ORDER BY id` dan menolak lintas tenant 404. Dua temuan awal saya (consume melanggar `slot_reservations_consumed_at_check`, `updated_at` tidak disentuh) **sudah teratasi** oleh edit 15:29.
- **Audit availability (snapshot sekarang)**: probe saya memverifikasi `tenant.availability.slot.created|closed|capacity_reduced|reopened` tertulis dengan actor sesi, target slot, dan reason; close/capacity-down tanpa reason -> 400. (Dokumentasi & test-nya belum menyusul — R2-05/R2-06.)
- **Validasi DTO**: `whitelist`+`forbidNonWhitelisted`+`transform` global; uang berpola `^(0|[1-9][0-9]{0,37})$`; `expectedVersion` wajib (min 1); `reason` 1..300; `capacity` 1..int4max; `startsAt/endsAt` pola ISO-8601; tanggal lokal `YYYY-MM-DD`; tidak ada endpoint yang menerima harga/total/status/versi sebagai otoritas (kecuali `status` slot yang memang aksi manajemen berizin).
- **Error contract**: semua error domain memakai `HttpException` sehingga `ApiExceptionFilter` memberi `{error:{code,message,request_id}}`; tidak ada pesan yang membocorkan SQL (kelas status untuk 23503/40P01 yang salah dicatat di R2-07).
- **OpenAPI katalog**: 16 operasi katalog terdokumentasi (termasuk respons 400/401/403/404/409 pada rute admin).
- **Dokumen katalog**: `docs/modules/catalog.md` akurat terhadap kode (rumus, audit, arsip, endpoint, batasan kategori tanpa version) kecuali tidak menyebut risiko deadlock (R2-04).
