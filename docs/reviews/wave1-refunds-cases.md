### Catatan yang diterima (bukan temuan)

- Akun system orders.payment.escrow boleh negatif karena `wallet_accounts_balance_nonnegative_check` memang mengecualikan account_type='system' (`drizzle/0003_rainy_jetstream.sql:44`), sesuai D16.1 ("kecuali dinyatakan lain oleh constraint yang sudah ada"). Karena refund hanya lahir dari order_payments.status='succeeded' yang pada checkout mengkredit escrow, tidak ada jalur overdraw nyata hari ini. Rekonsiliasi escrow tetap pekerjaan wave operasional.
- POST /v1/campuses/:campusId/cases (tulis) dijaga campus.cases.read karena D10 melarang menambah nama permission baru. Konsisten dengan keputusan root, tetapi perlu diingat saat permission granular ditinjau.

- Amount diambil dari order_payments (`refunds.service.ts:266-279`) dan disimpan ke refunds.amount_minor; kredit memakai nilai tersimpan itu (`:707`), bukan nilai dari request.
- Idempotency ledger diturunkan dari refund: scope refunds.sandbox.credit, key = refund.id, reference {namespace:'refund', id:refund.id} (`:701-715`), sesuai D17 butir 4. Bukan payload klien.
- Replay provider event tidak menggandakan: event id = providerReference + ':refund.succeeded' dengan on conflict (provider, event_id) do nothing (`:671-687`), ditambah lock for update + guard status (`:636-661`) dan guard transisi where status in (...) and succeeded_at is null (`:716-738`).
- providerReference deterministik dari (refundId, orderId, amountMinor) (`refund.adapter.ts:75-87`) dan divalidasi tidak berubah antar-attempt (`:662-669`).
- Diuji: `test/refunds.spec.ts:545-632` (kredit tepat sekali + ledger seimbang), `:634-679` (replay), `:681-741` (failed tanpa kredit), `:743-824` (pending/needs_assistance tanpa kredit).

### 6. Processor/queue

- Adapter dipanggil **di luar** transaksi/lock: lease via satu statement autocommit (`refunds.service.ts:525-536`), baca refund via pool (`:551-554`), adapter.submitRefund (`:578-587`), baru kemudian transaksi terpisah per outcome (`:635`, `:784`, `:895`).

Diuji `test/refunds.spec.ts:743-824`, `:886-912` (lease aktif di-skip, lease kedaluwarsa diambil alih).
- Dedupe provider event: unique (provider, event_id) (`refunds.ts:159-162`) + on conflict do nothing (`:671-687`).
- jobId nonce mencegah stall (P2-01): 'refund-request-' + refundId + '-' + attempts + '-' + nonce dengan nonce = updated_at mikrodetik (`refund-request.processor.ts:72-73`, `refunds.service.ts:494-495`), plus hapus job failed lalu re-add (`:81-89`) dan alarm baris due > 120s (`:61-71`).
