## 4. Yang sudah benar (cakupan terverifikasi positif)

- **Kredit tepat sekali dengan 4 lapis pertahanan** dan bukti test konkurensi nyata (event id sama & beda) — saldo, jumlah credit ledger, jumlah provider event semuanya diassert.
- **Jumlah kredit selalu dari intent tersimpan**, tidak pernah dari payload webhook; korelasi currency/amount(BigInt)/state sebelum mutasi apa pun; setiap outcome (applied/duplicate/ignored/mismatch/unmatched/conflict) tercatat di `payment_provider_events` → jejak rekonsiliasi lengkap; payload hanya disimpan sebagai hash.
- **HMAC fail-closed**: byte persis via `rawBody`, constant-time, jendela replay ±300s, secret kosong ditolak, `occurredAt` historis (late success) didukung dan dipisahkan dari timestamp autentikasi — persis rencana HANDOFF.
- **Production menolak sandbox di 3 lapis independen** (Joi env, providerMode, adapter) + mode disabled = 503 eksplisit, tanpa sukses palsu; guard DB `provider='sandbox'` (0006) sebagai lapis ke-4.
- **Atomis & idempoten**: intent+outbox+audit satu transaksi (rollback teruji); replay idempotency requestHash; dedupe keuangan lewat unique constraint sesuai D7 poin 5, bukan timestamp.
- **Worker disiplin**: panggilan provider di luar lock/tx; seluruh state retry (lease fencing, backoff, cap, dead+error code) otoritatif di PostgreSQL sehingga redelivery BullMQ tidak bisa menggandakan efek; tidak ada duplikasi registrasi queue; dispatcher tidak memegang lock PG saat bicara ke Redis.
- **Tenant/campus**: semua otorisasi server-side dengan client transaksi; D7 diimplementasi benar (string mikrodetik dari `to_char`, dibandingkan sebagai parameter, round-trip HTTP teruji); archive = 4 blocker dependensi nyata + serialisasi FOR UPDATE + riwayat dipertahankan + archived→404 di semua permukaan (publik, admin, requireTenant).
- **Provisioning tanpa backdoor**: tidak ada route publik pemberi akses kampus; bootstrap owner mengikuti D9 detail demi detail (advisory lock identik dengan AccessService, 409- sebelum-probing-subject, guarded upsert anti-timpa-owner, triple audit atomik); keterbatasan `access_audit_events` untuk service actor ditangani sesuai D9 dan diassert eksplisit.
- **Jam operasional = sumber tunggal D8** dengan kontrak beku, konvensi weekday D12 terdokumentasi di kode+DTO+docs, validasi service mencerminkan CHECK DB dan keduanya teruji (termasuk insert langsung di belakang service).
- **Uang**: integer minor string desimal di semua lapisan (DTO pattern, service BigInt, DB numeric); tidak ada `Number` di jalur uang; tidak ada float.
- **Dokumentasi modul akurat** terhadap kode, termasuk batasan yang jujur (tidak ada expiry sweeper, `needs_assistance` belum dipakai, jendela lintas tengah malam belum, list endpoint tanpa cursor, outbox event tenant ditunda root).
